When the user says "the JARVIS app" they mean C:\Users\User\Downloads\JARVIS_App - an Electron desktop app that wraps Claude Code (Agent SDK) for the Bantu Apps workspace, with a Telegram bot as a remote keyboard (src/remote.mjs, src/telegram.mjs). Not the Bantu2U product repos. An older separate bot lives at C:\Users\User\jarvis-telegram-bot.

Since 2026-10-06 (v1.6.0) there is an installer: `npm run dist` writes `dist-installer\JARVIS-Setup-<version>.exe` (NSIS, per-user, installs to %LOCALAPPDATA%\Programs\JARVIS). Settings > Updates checks JARVIS (GitHub `releases/latest`, needs a `JARVIS-Setup-x.y.z.exe` asset), VS Code (winget) and Claude Code (`claude update` or npm). The JARVIS update downloads the installer, checks its SHA-256, quits, runs `/S`, and reopens with `--updated`. Releases: everything stays in the PRIVATE repo Silentt9879/JarvisApp (user's explicit rule: no second repo). JARVIS_REPO = JarvisApp. Anonymous GitHub calls get 404, so the app signs in: it uses the sign-in Git already has (credential store, silent), or a token the user pastes once in Settings > Updates, stored encrypted with safeStorage (github-token.bin in userData). Latest release is v1.7.3 on JarvisApp (2026-10-07). The user confirmed on 2026-10-07 that the in-app update works and brings the window back (fixed in 1.7.2). They install each new version themselves from Settings > Updates; the updater was made to work in 1.6.2 with WMI. Do not press Update from inside a chat that runs in JARVIS itself (the restart ends that session). Sign-out, restart and folder buttons were fixed in 1.6.1. The stray public repo Silentt9879/JarvisReleases was made PRIVATE (the token lacks delete_repo scope); the user should delete it on GitHub, it is no longer used. To publish a new version: bump package.json, npm run dist, commit and tag, then create the release on JarvisApp and upload the .exe through the REST API, with the token from `git credential fill` for github.com (gh and python are not installed, so Node's fetch does the upload; see [[jarvis-release-pushes]]). The v1.6.0 build was swapped into the running copy (dist\win-unpacked) on 2026-10-06; check swap-update.log for the outcome. Code: src/updates.mjs, src/renderer/updates.js, scripts/updates-test.mjs. Older dev build flow below still applies to the dist\win-unpacked copy.

Build beside the running copy with `npx electron-builder --dir "-c.directories.output=dist-next"` (quote it in PowerShell, or the arg gets split and the build fails), then the user closes JARVIS and dist-next\win-unpacked replaces dist\win-unpacked. Don't run a non-capture dev instance while theirs is open - both would read the same Telegram bot.
